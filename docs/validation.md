# Validation

Generated by `npx tsx scripts/validation-report.ts` (do not edit by hand). The same rows are in `src/validation.json` and appear in the app under "Assumptions & validation". Case definitions, computations and acceptance live in `tests/helpers/validation.ts`; `npm run test:validation` asserts them.

Every geometry is checked against a closed form, an exact limit or a published reference (spec §7). Status:

- **pass**: an exact limit, the solver's own convergence, or the reference's stated accuracy is met;
- **deviation recorded**: the reference publishes no accuracy, or the result is outside it. Per the failed-validation policy (spec §5) it was investigated with an independent second reference (a finite-difference solve, below) and the convergence check; the second reference agrees with the solver within 0.5 %, so the solver holds and the measured deviation of the formula is shown here and on the page;
- **not validated**: no reference exists (solder mask: sensitivity only), or the feature is not in this build yet.

Zero-thickness reference geometries (V3–V6, V9–V12): stripline, microstrip and CPWG go through the Stackup model with T set to 0 afterwards (the model refuses copper of thickness 0). The open-side geometries (embedded microstrip, CPW without backside metal: V10, V11, V12a) are hand-built cross-sections, because on an open side the model turns the far copper of a stackup into a "cut out" slab of dielectric that is not part of the reference geometry (through the Stackup route it made the 1e-6 mm-cover embedded line read −5.6 % against plain microstrip). A test checks that the hand-built ones equal the model's cross-sections minus that slab.

The published Wadell / IPC-2141A formula adds a correction term ΔZ0,air for exactly that coupling, but its printed form could not be verified in an open source (the one reproduction found contains an evident typo), so it is left out (refs.ts). This row therefore records the error of the uncorrected term, not of the full published formula.

The error is larger at the stronger offset; at the same offset it is larger for the narrower trace. An independent image-Green's-function method-of-moments check agreed within 0.05 % (not pinned here). The solver holds; the deviation is the uncorrected term's.

The finite-substrate formula at h = 8.0 mm differs from the infinite one by +0.0033 %, so the substrate is thick enough.

Dom 1 vs 2 is driven by the mesh, not by the far boundary. With h = 8 mm the open-side air depth is D = 30·h = 240 mm (480 mm at dom 2), and the grid builder integrates its grading function with a fixed 200 samples per key interval, so the first cells next to the coplanar-ground edge and above the trace come out 14× (dom 1) and 27× (dom 2) larger than hmin. Measured when this check was set up: the raw meshes converge slowly (dom 1, q 1/2/4/8: 64.52 / 70.49 / 73.39 / 74.81 Ω) and Richardson carries the result (rich(2,4) 76.29, rich(4,8) 76.23 against an exact 76.201 Ω). At dom 2 the observed order drops to about 0.84 and the order-1 Richardson overshoots, hence the larger dom 2 errors. Acceptance is evaluated at dom 1, the domain the app uses. The dom 2 values are recorded as the domain sensitivity of this 8 mm test substrate (open-side air depth 240 mm at dom 1, 480 mm at dom 2); the convergence check V7 on the example stackup's CPW without ground passes.

On realistic CPW-without-ground cases on the example board (F.Cu, no references, mask 0, q 2; W/G 0.2/0.15, 0.3/0.2 and 0.5/0.5 mm; independent measurement), dom 1 vs dom 2 moves Z0 by −0.036 %, −0.026 % and −0.009 % and εeff by under 0.01 %.

The scripts are in `scripts/fd-reference/` (optional: Python with numpy and scipy; not part of the build). Its values are pinned in `tests/helpers/validation.ts`.

- **Extrapolation to d → 0.** Where three grids (d = 0.01 / 0.005 / 0.0025 mm) all resolve the geometry, the observed order (0.97–1.0) is used. Several deviation cases use only two grids with order 1 assumed: the coarsest grid puts some strip, slot or cover edges off the grid, and a grid finer than 0.0025 mm (0.005 mm for two covers) was not run.
